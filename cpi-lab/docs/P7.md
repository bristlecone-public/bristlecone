# P7 — tariff-exposed vs domestic CPI

**Owner:** `pipelines/p7_tariff.py`, `pipelines/tariff_timeline.csv`, this file.
**Runtime:** the pipeline host `cpilab`, `$CPI_ROOT/p7_tariff.py`. **Output:** `$CPI_ROOT/out/p7_tariff.json`.
**Status:** live, first end-to-end run 2026-08-25 against CPI through **2026-07**.

---

## 1. Plain language

### What it does

Every item in the CPI basket is made somewhere. A pair of shoes is mostly made abroad;
a haircut is entirely made here. P7 works out, for each of the 179 CPI leaf items, **how
much of a dollar you spend on it ends up paying for something that crossed a border** —
then splits the basket into three groups and builds a separate inflation index for each.

- **Exposed** — items where 25% or more of the consumer dollar is imported content.
  43 items, **12.6%** of the basket. Computers, small appliances, cookware, televisions,
  audio equipment, luggage, phone hardware, seafood, men's suits.
- **Mid** — 10% to 25%. 81 items, **19.9%** of the basket.
- **Domestic** — under 10%. 55 items, **65.2%** of the basket. Shelter, most medical care,
  education, personal services, insurance, utilities.

There is also a **headline replica** built the same way over all 179 items, which lets you
check the three tiers against something you already recognise.

### What it does not do

It does not measure the effect of tariffs on prices. The three aggregates are
re-weightings of published BLS item indexes — descriptive, nothing more. If exposed-tier
inflation runs above domestic-tier inflation, that is a fact about two groups of prices;
the reason could be tariffs, or the dollar, or shipping rates, or the fact that goods and
services have been on different paths since 2021.

The one output that gestures at causality is the **event study** (section 4), and it is
deliberately fenced off: it is Tier 2, it carries pre-trend checks, and **10 of the 25
events it estimates fail those checks**. Read the flag before the number.

### Latest reading (2026-07)

| Series | YoY |
|---|---|
| Exposed (import content ≥ 25%) | **+2.79%** |
| Mid (10–25%) | **+4.61%** |
| Domestic (< 10%) | **+2.98%** |
| Headline replica (all leaves) | **+3.29%** |

The exposed tier is running *below* the domestic tier (−0.19pp) and below the headline.
That is not what a naive tariff story predicts, and it is worth saying plainly: over the
window the tariffs have been in force, the most import-intensive part of the basket has
not been the fastest-rising part. The mid tier is the fastest, which is largely a
composition fact — it contains new and used vehicles, food away from home and apparel.

**But "Exposed below Domestic" is not evidence that tariffs did nothing — it is a
category confound.** The Exposed basket is loaded with hedonically-deflating tech durables
(computers, TVs, audio, phone hardware, appliances), whose quality-adjusted CPI indexes fall
**5–15% a year** in normal times because BLS strips out performance gains; the Domestic basket
is dominated by Baumol-effect services (shelter, medical care, education, personal services)
that carry a structural positive drift regardless of trade policy. So the two tiers were on
divergent trajectories *before any tariff* — tradable durables deflating, sticky services
rising — and a raw Exposed-vs-Domestic gap mixes that pre-existing category difference with
whatever tariffs did. A tariff could push exposed-goods inflation up several points and the
tier could *still* print below services. **The cleaner descriptive test is
Exposed goods vs Domestic goods** — hold the goods/services mix fixed on both legs so the
comparison is durable-tradables against domestic-tradables, not tradables against services.
That goods-vs-goods index is **not built here yet** (it needs a fourth aggregate restricted to
the 126 CPI goods items on both tiers, a code change beyond this pass — see §4); it is the
recommended benchmark for reading the tiers as a tariff signal, and until it exists the
event study in §4, not the tier levels, is the only part of this pipeline that gestures at
causality.

### How much of the basket is imported?

| Measure | Value |
|---|---|
| Import content of PCE, weighted by PCE spending | **11.8%** |
| Import content of the CPI basket, weighted by CPI relative importance | **9.9%** |
| Import content of the CPI **goods** basket (126 items, 30.6% of basket weight) | **22.4%** |
| Direct-only import content of PCE, BEA annual tables, 2023 | 6.0% |

The 11.8% figure is the one to compare against the published ballpark of 10–12% of PCE,
and it lands inside it. The CPI figure is lower because the CPI weights shelter at ~33%
of the basket versus ~15–18% in PCE, and shelter is entirely domestic.

2. **The annual summary Use table is not at a guessable URL.** It only exists inside
   `AllTablesSUP.zip`, and that zip lives under `iTables Static Files/`, not under
   `xls/io-annual/`. `AllTablesIO.zip` under `xls/io-annual/` is a stale 1997–2013 vintage
   and is not what you want.

### The PCE-bridge path ran

The brief allowed a fallback in case the bridge could not be obtained. It could be, so
the **primary path ran**: `method = det2017_bridge_leontief`, `path = bridge`. The
fallback (`commodity_haircut`, a uniform per-major-group margin haircut) is still in the
code and will engage automatically if BEA moves the bridge, and it labels itself in the
JSON so downstream consumers can tell.

Having the bridge matters more than it sounds. The margin share of a consumer dollar is
not a constant "goods at retail ≈ 30–40%" — the bridge shows it ranging from **12.5%
producer share** (games and toys, where nearly seven eighths of the price is
transport plus wholesale plus retail margin) to **73.8%** (nonelectric cookware) across
goods categories, and 100% for services. A uniform haircut would have mis-stated
import content by a factor of two at both ends of that range.

## 3. Method (technical appendix)

### 3.1 Commodity-level import content

For benchmark year *B* (2007, 2012, 2017 all computed; 2017 is the operative basis):

Let `U` be the Use table (commodity × industry + final use, producers' prices), `M` the
import matrix on the same grid, `V` the Make table (industry × commodity), `L` the
commodity-by-commodity **domestic** total requirements matrix.

**Direct import share of a PCE dollar on commodity *c*:**

```
sd_c = M[c, F01000] / U[c, F01000]                          clipped to [0,1]
```

`F01000` is the PCE column. For the 127 of 402 commodities with negligible PCE use, the
denominator falls back to total use across all non-total columns excluding `F05*`
(the negative "imports" reconciliation column the I-O Use table carries). 274 commodities
use the PCE column directly.

**Imported intermediates embodied in a dollar of domestic commodity output:**

```
mi_j = ( Σ_c M[c,j] ) / x_j            direct imports per $ of industry j output
D[j,c] = V[j,c] / q_c                  industry j's share of commodity c output
mc     = mi · D                        re-expressed per $ of commodity output
t      = mc · L                        Leontief total: direct + all indirect rounds
```

`x` is industry output (row sums of `V` over commodity columns only) and `q` is commodity
output (column sums over industry rows only). **Both sums must exclude the total
row/column** BEA ships in the Make table — including it silently halves every import
intensity. On the 2017 basis the corrected result is mean `t` = 0.140 with a max of 0.566;
before the fix it was 0.035 / 0.142, which is what a doubled output denominator looks like.

**Total import content of a PCE dollar on commodity *c*:**

```
st_c = sd_c + (1 - sd_c) · t_c
```

The dollar splits into an imported part `sd_c` and a domestically produced part
`1 - sd_c`; only the domestic part carries embodied imports.

### 3.2 From commodities to CPI items

The PCE Bridge gives, for each NIPA PCE category *p*, the split of purchasers' value into
Producers' Value per commodity, Transportation, Wholesale margin and Retail margin.
Margins and transport are domestic services: they carry no *direct* import content, only
the embodied content of the trade and transport commodities (2017: wholesale 0.053,
retail 0.041, transport 0.094, output-weighted over the matching detail commodities).

```
share_direct_p = Σ_c PV_pc · sd_c / PU_p
share_total_p  = ( Σ_c PV_pc · st_c + WS_p·t_ws + RT_p·t_rt + TR_p·t_tr ) / PU_p
```

`P7_MAP` in the source then maps each of the 179 CPI leaf items to one or more NIPA PCE
categories with shares summing to 1, and the item's share is the share-weighted mean.
**All 179 leaves are mapped**, services included — the domestic tier is built from
computed near-zero shares, not from "everything we failed to map".

`P7_MAP` is keyed on NIPA line numbers **and** carries the expected category description.
NIPA line numbers move at comprehensive revisions, so every lookup is description-checked
and a mismatch is logged and dropped rather than silently mapped to the wrong category.

**One override.** BEA allocates a commodity's imports proportionally across its users, so
"New foreign autos" does not come out 100% imported. `PCE_DIRECT_OVERRIDE` forces NIPA
line 8 to a direct share of 1.0 at producers' value. It is the only such override and it
is declared in the JSON method flags.

### 3.3 Why 2017 and not something current

BEA publishes the detail Use / Make / import / total-requirements set only for benchmark
years. Exposure is therefore measured in **2017 — before every tariff in the timeline**.
That is a genuine advantage for the event study: the tier assignment cannot be
contaminated by the tariffs being studied, or by re-sourcing in response to them. It is
also a genuine limitation for the descriptive series: any supply chain that moved after
2017 is mis-classified, and the direction of that error is toward overstating exposure
for anything that reshored.

The 2007 and 2012 bases are computed and stored so the drift is visible:
average `share_total` across the 179 leaves is 0.190 (2007), 0.197 (2012), 0.177 (2017).

The annual summary import matrix (1997–2023) is loaded but **deliberately not crosswalked
to items** — it feeds only the economy-wide `pce_import_content` context series and
validation. Building a detail↔summary commodity crosswalk to get annual per-item shares
would add a second hand concordance for a series that changes by about a point a decade.

### 3.4 Tier cutoffs

`CUT_HI = 0.25`, `CUT_LO = 0.10` on `share_total`. The distribution over the 179 leaves
on the 2017 basis:

```
min 0.005   median 0.158   p75 0.244   p90 0.367   p95 0.393   max 0.589 (computers)
mean 0.177  sd 0.119
```

The cutoffs are round a-priori thresholds, not natural breaks — and `CUT_HI = 0.25` in
fact falls almost exactly at the p75 of the realised distribution (0.244). The mass is
**not** bimodal: it is single-peaked near 0.05–0.10 (the mode) with a long right tail, and
there is no gap at either cutoff — 35 of the 179 leaves sit within ±0.05 of 0.25 and 75
within ±0.05 of 0.10. Tier membership near a boundary is therefore sensitive to the exact
threshold: moving `CUT_HI` from 0.25 to 0.30 reclassifies 12 items, moving it to 0.20
reclassifies 21, and about 9% of basket weight sits in [0.20, 0.30) straddling the line.
Read the tiers as coarse buckets, not as a natural break in the data. The resulting weight
split — 12.6% exposed, 19.9% mid, 65.2% domestic — still keeps the exposed leg small
enough that it is dominated by genuinely traded goods rather than by a few heavy service
items sneaking in.

### 3.5 The three aggregates

`Chainer` is **copied verbatim from `p1_salience.py`**, not imported, so the arithmetic is
identical to the P0/P1 December-chained Laspeyres replica:

```
I_t = I_Dec · Σ_i w_i · P_it / P_iDec  /  Σ_i w_i
```

with December relative-importance weights of year *Y* applied to the months of *Y+1*,
renormalised within each tier. `MIN_COV = 0.90`: a month is dropped unless leaves carrying
90% of the scheme's weight have both a December base and a current index. October 2025
(no CPI release — shutdown) is dropped from every scheme, at 34.2% / 14.6% / 5.8% / 11.3%
coverage for exposed / mid / domestic / replica. November 2025 is additionally dropped
from the **mid** scheme at 86.0% coverage; that is the gate working as designed on a
narrower weight base, and it means the mid series has a two-month hole where the others
have one.

`official_replica` matches `p1_index.official_replica` to **0.0000pp** at every month —
the tolerance was 0.02pp.

## 4. Event study (Tier 2 — report, do not headline)

### Design

For each event the estimating equation is run on the **weighted exposed-minus-domestic
gap in demeaned month-over-month inflation**, as a time series:

```
G_t = Σ_{i∈exposed} w_i·x_it / Σ w_i  −  Σ_{i∈domestic} w_i·x_it / Σ w_i
```

where `x_it` is item *i*'s NSA month-over-month change minus that item's own mean for that
**calendar month**, computed over all months more than 12 away from the event so the event
cannot demean itself away.

- **NSA throughout, for both legs.** Mixing SA items with NSA-fallback items would put a
  seasonal wedge straight into the difference (the P3 lesson). Seasonality is removed by
  the item × calendar-month demeaning instead.
- Sample: ±24 months around the event. Dummies for relative months −6…+12; −24…−7 is the
  omitted baseline. **Newey-West HAC standard errors, 6 lags.**
- Reported: per-horizon coefficient and SE, the cumulative 0…+12 effect with its SE from
  the full coefficient covariance, and a **pre-trend test** — OLS slope of `G_t` over
  relative months −6…−1 with HAC(2) SEs, flagged as failing when |t| > 2.
- `p7_event` stores the underlying item × relative-month panel (39,558 rows over 28
  events, 43 exposed items vs 55 domestic items) with both demeaned MoM and demeaned YoY.

### Event selection

87 timeline rows → **28 events**. A row is eligible if confidence is high or medium and
|ad-valorem change| ≥ 5pp. Monthly CPI cannot separate two actions in the same month, so
each month contributes at most one event, chosen by **duty impulse** = |rate change in pp|
× annual import value covered, not by the largest rate change — a 50pp rate on one partner
moves the consumer basket far less than a 10pp rate on everything. Ties go to the broader
base. Every other row sharing the month is recorded in `bundled_actions`, and where three
or more rows share an action family the event is labelled by the family (`s301_4yr`).

Import values are read from the `scope` text where it states one. Where it does not, a
**product-specific** action gets a small placeholder rather than the named partner's whole
import total — without that guard "China, electric vehicles" would be scored as if it
covered all $440B of Chinese imports. These values rank events. The chosen event's value
and duty impulse are also written per event into `event_study`
(`covered_import_value_bn` / `duty_impulse_bn`) in the public JSON, so for a
product-specific action with no stated value that field carries the placeholder — it is
ranking metadata, not a measured trade volume, and must not be read as one. (The dashboard
does not surface these fields.)

### The 2025 universal-tariff result

**2025-04-05, `ieepa_baseline`** — the IEEPA universal 10% reciprocal baseline (EO 14257),
bundled with `s232_autos`, `ieepa_electronics_exclusion`, `ieepa_reciprocal_annex1`,
`ieepa_china_84`, `ieepa_china_125` and `ieepa_reciprocal_pause`, all of which took effect
in the same month.

```
cumulative effect, months 0..+12   +2.33 pp   (HAC se 1.29)
pre-trend slope, months -6..-1     +0.0777    (t = +0.79)      PRE-TREND OK
```

Exposed-tier month-over-month inflation ran cumulatively **2.33pp above** domestic-tier
over the year following, with a standard error of 1.29pp — about 1.8 standard errors, so
suggestive and not significant at conventional levels. The pre-trend check **passes**:
over the six months before the event the gap was not already trending (t = +0.79).

That is the strongest thing this pipeline says, and it is still weak. It is a difference
between two groups of prices around a date on which six other tariff actions also took
effect, in a month that also saw the largest equity and dollar moves of the year. It is
not an estimate of the pass-through of a 10% tariff.

### Known weaknesses

- **Tier assignment, not treatment assignment.** Import content is not tariff exposure.
  A high-import item sourced entirely from a country that was never tariffed is in the
  exposed tier anyway.
- **Overlapping windows.** With 28 events in 100 months, most ±24-month windows contain
  other events. Each regression treats the others as noise.
- **One-per-month bundling** is a real loss of resolution, not a technicality — the April
  2025 estimate cannot separate the universal baseline from the auto tariffs.
- **Composition — the hedonic/Baumol confound.** The exposed tier is 12.6% of the basket and
  is durable-goods heavy; the domestic tier is shelter heavy. Anything that moves durables
  relative to shelter shows up here regardless of trade policy. Concretely: the exposed basket
  carries the hedonically-deflating tech durables (computers, TVs, audio, appliances, phone
  hardware) whose quality-adjusted indexes fall 5–15%/yr, while the domestic basket carries the
  Baumol services (shelter, health, education) that drift structurally positive. So an
  "Exposed below Domestic" reading is expected from category composition alone and is **not**
  evidence tariffs had no effect. **Recommended fix (not implemented):** add an
  **Exposed-goods vs Domestic-goods** pair of aggregates — restrict both legs to the 126 CPI
  goods items so the comparison holds the goods/services mix fixed. That is a proper code change
  (a fourth `Chainer` scheme plus a goods filter on `p7_tier`, a new `p7_index` scheme, its own
  `MIN_COV` gate and a dashboard line); it was judged too large to fold into this documentation
  pass safely, so it is logged here as the benchmark to build next rather than added now.

## 7. Maintenance — read this before adopting the pipeline

**This pipeline's real cost is curation, not compute.** The code runs in about 80 seconds.
Keeping it honest is an ongoing manual job, and it will silently rot if nobody does it.

### 7.1 The tariff timeline (~30 minutes per event, ongoing)

`pipelines/tariff_timeline.csv` is **data, not code**, and it is hand-curated. Nothing
updates it automatically and nothing ever will — there is no machine-readable feed of US
tariff effective dates with rates.

Adding one event properly takes roughly half an hour: find the Federal Register or USTR
document, establish the **entry/withdrawal date** (not the announcement date — they differ
by weeks and the announcement is the one the press reports), work out the *change* in the
ad-valorem rate rather than the level, and record the source URL. `govinfo.gov` usually
serves documents that `federalregister.gov` and agency sites block.

Conventions to preserve:

- `effective_date` is the date duties began to be **collected**.
- `ad_valorem_change_pp` is the **change**, not the level (10→25% is `15`).
- Where one legal action changed dozens of rates at once, the literal string `varies` is
  used rather than inventing a single number. These rows are excluded from the event study
  (they parse to NaN and fail the ≥5pp filter) but are still published in the JSON
  timeline. Seven rows are currently `varies`.
- Court rulings that vacate or stay tariffs get rows too, at `0` pp — they are events even
  though they are not rate changes.
- Actions that were **announced but never took legal effect** must not be added. Three
  were caught during the initial build: the October 2025 100% pharmaceutical tariff, the
  August 2025 100% semiconductor tariff, and a January 2026 wood/furniture step-up that
  was postponed a year. All three were widely reported as if they had happened.
- `confidence` is `high` only when a primary source was read. Six current rows are
  `medium` (law-firm or tax-alert sourcing, or an inferred rate) and are named in the file.

### 7.2 The annual BEA refresh (~1 hour, every September)

BEA adds a year to the annual I-O accounts each September. When that happens:

1. `ImportMatrices_Before_Redefinitions_SUM_1997-2024.xlsx` starts resolving.
   `bea_annual_url()` already probes `_1997-2024` first and falls back to `_1997-2023`,
   so **this flips by itself** — the log line `not published yet` becomes `resolved`.
   Extend `BEA_IM_SUM_ENDS` at the front each year (`[2025, 2024, 2023]`) so the probe
   keeps looking one year ahead.
2. `Use_Tables_Supply-Use_Framework_1997-2023_Summary.xlsx` inside `AllTablesSUP.zip`
   gets a new year range in its filename. `SUP_USE_SUM` is a hardcoded constant and
   **will break**. It is the one place the annual refresh needs a human. Symptom: the
   `annual PCE direct import content` log line disappears and the
   `annual_direct_import_share_of_pce` check vanishes from the validation list.
3. Benchmark years only move every five years. The next detail benchmark is **2022**,
   expected around 2029. When it lands, add 2022 to the basis loop and the bridge sheet
   list, and consider moving `--basis` to 2022 — but weigh that against the argument in
   §3.3 that a pre-tariff basis year is what makes the event study defensible. It may be
   right to keep 2017 as the event-study basis and publish 2022 alongside.

### 7.3 Things that will drift quietly

- **NIPA line numbers** in `P7_MAP` move at comprehensive NIPA revisions. The
  description check catches this and logs `P7_MAP: <item> -> NIPA line N (...): description
  drift`, then drops the row. **Check the log for that string after every BEA refresh** —
  a dropped row does not fail validation, it just quietly reduces coverage. The
  `P7_MAP covers all 179 leaf items` line is the one to watch.
- **CPI item codes and titles.** New leaf items appear at weight refreshes. An unmapped
  leaf is logged (`P7_MAP covers N/179`) and lands in the domestic tier with a share of 0,
  which is wrong for anything traded. Add it to `P7_MAP`.
- **BEA filename churn.** Every URL is a module constant with a comment. If a fetch
  starts returning a 26 KB HTML page, that is a 404 wearing a 200.

### 7.4 Running it

```bash
# in the pipeline host
cd $CPI_ROOT && ./p7_tariff.py                 # full run, ~80 s
./p7_tariff.py --refresh-bea                  # force re-download of the BEA workbooks (~35 MB)
./p7_tariff.py --no-event --no-mxp            # aggregates only, for a quick check
./p7_tariff.py --basis=2012                   # tier on a different benchmark year
./p7_tariff.py --help
```

**Cron.** P7 needs `cpi_item_month` (P0) and reads `p1_index` for its replica check, so it
belongs in the new-data branch **after P1**. The line to add to `run_monthly.sh`, after
`run p10 ./p10_network.py`:

```bash
run p7 ./p7_tariff.py
```

It should run **only when P0 reports new data** — the aggregates only change when CPI
changes, and the BEA workbooks are Last-Modified-cached so a re-run costs nothing but
also gains nothing. It does **not** need adding to the February weight-refresh chain
strictly speaking, but adding it there is harmless and keeps `p7_tier` in step with
re-parsed weights; if you do, put it after `run p3` in that block.

The annual BEA refresh does not need a cron entry — the monthly run picks up the new
files automatically once §7.2 step 2 has been done by hand.
