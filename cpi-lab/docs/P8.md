# P8 — where households substitute: C-CPI-U vs CPI-U

`pipelines/p8_chained.py` → tables `p8_obs` / `p8_obs_latest`, `p8_item`, `p8_gap`,
`p8_vintage`, `p8_revision`, file `out/p8_chained.json`

BLS publishes two headline price indexes off the *same* underlying price quotes. The CPI-U
combines them with fixed, lagged expenditure weights. The **Chained CPI-U (C-CPI-U)**
combines them with a formula that uses spending patterns from both the start and the end of
the period, so it registers the fact that when beef gets expensive people buy more chicken.
The C-CPI-U is always the lower of the two. P8 measures that difference — for the headline
and for each of the 29 categories BLS publishes both ways — and tracks how the chained index
gets revised over the following year.

---

## Part 1 — in plain language

### What substitution bias is

A fixed-weight index answers a very specific question: *what would last year's shopping
basket cost today?* That is a useful question, but it is not quite "what happened to the cost
of living", because nobody actually buys last year's basket. When the relative price of
something jumps, households buy less of it and more of something else. A fixed-weight index
keeps charging you for the old quantities, so it drifts above what people actually end up
spending. The gap is called **substitution bias**, and it comes in two layers:

* **lower-level** — swapping between varieties *inside* a category (this brand of coffee for
  that one). BLS already handles this: since 1999 most CPI categories are averaged with a
  geometric mean, and the C-CPI-U uses the exact same geometric means. So this layer is
  **not** in P8's numbers.
* **upper-level** — shifting spending *between* categories (less driving, more streaming).
  The CPI-U cannot see this until the weights are next updated. The C-CPI-U can. This is the
  layer P8 measures.

### The one number

    gap_yoy  =  CPI-U 12-month % change  −  C-CPI-U 12-month % change     (percentage points)

Positive means the fixed-weight index rose faster. **Since December 1999 the all-items gap
has averaged 0.269 percentage points per year** — CPI-U 2.586%/yr against C-CPI-U 2.317%/yr
through September 2025 — which lines up with the ≈0.25pp figure BLS and CBO cite. Compounded
over 25.75 years that is **6.99%**: a benefit indexed to the chained measure since 2000 would
today be about 7% smaller than one indexed to the CPI-U. That single fact is why "chained
CPI" keeps appearing in budget proposals.

### The gap is shrinking

Part of this is mechanical rather than behavioural. Through 2022 the CPI-U used **two-year-old,
two-year-long** expenditure weights; from January 2023 BLS switched to **single-year weights
updated every January**. Fresher weights track spending shifts sooner, so less of the
divergence is left for the chained index to pick up. Do not read the 2026 number as "people
stopped substituting".

### The three-stage revision

The chained formula needs to know what people spent *this* month, and that information arrives
about a year late. So BLS publishes every month three times:

1. **Initial** — with the month itself, using an approximation.
2. **Interim** — revised each quarter, with the January, April, July and October releases.
3. **Final** — 10–12 months later, once the actual expenditure data are in.

As of the current data (through July 2026): **final** through 2025-09, **interim** for
2025-11 … 2026-06, **initial** for 2026-07. The dashboard should label the latest months
accordingly — the newest gap number is the least reliable one on the chart.

How big are the revisions? From 106 all-items months whose initial print we recovered
(2017-07 onward), 97 of which are now final:

* mean revision to the published **level**: −0.13% (77% of months are revised **down**)
* mean absolute revision to the **12-month change**: **0.274 pp**; largest 0.783 pp (May 2023)

That number deserves a moment. The average revision to the initial 12-month change is
*larger than the average gap itself*. **A single month's initial-stage gap carries no
information.** The long-run average is solid; this month's reading is not. Anyone quoting
"the chained CPI says inflation was X" off a fresh release is quoting a number that will move.

## Part 2 — technical appendix

### Source

`https://download.bls.gov/pub/time.series/su/` — survey `SU`, Chained CPI-U.

| file | contents |
|---|---|
| `su.series` | 29 series, all `SUUR0000<item>`; area `0000` (U.S. city average), periodicity `R` (monthly), seasonal `U`, base `DECEMBER 1999=100` |
| `su.item` | the same 29 item codes, sharing the `cu.item` code scheme (`SA0`, `SAF11`, `SETA01`, …) |
| `su.data.1.AllItems` | the data — 9,616 rows, 1999-M12 … 2026-M07, including 364 `M13` annual averages |
| `su.data.0.Current` | **byte-identical** to `su.data.1.AllItems` (verified). The whole survey is one file; there are no per-group data files as there are for `cu` |
| `su.footnote` | **`I` = Initial, `U` = Interim** |
| `su.area`, `su.base`, `su.periodicity`, `su.seasonal` | single-row mapping files |

The directory index was listed and logged; the ten files above are everything in it.

**There is no fine-grained C-CPI-U.** The chained index does not exist at the `SE…` stratum
level on the flat file (or anywhere else public), only for these 29 aggregates. "Item level"
in P8 therefore means these 29, **not** the ~179 CPI leaf strata used by P1/P2. The
sub-directory is 891 bytes of item codes; that is the whole universe.

### Stage identification

The stage is carried in **`footnote_codes` on each data row of `su.data`**, not in the series
title and not in a separate file: `I` → initial, `U` → interim, **blank → final**. The flat
file only ever carries the *current* stage of each month, so it is a snapshot, not a history.
P8 therefore stores every download as a vintage in `p8_obs` (PK includes `pull_id`), exactly
like `cpi_obs`, with a `p8_obs_latest` view taking `MAX(pull_id)`. Unlike P0, a row is also
written when **only the footnote changed** — an interim month going final at an unchanged
level is a real event here and must not be dropped as a no-op.

### Reconstructed publication vintages

Waiting for revisions to accrue would leave the revision panel empty for a year, so history is
rebuilt from the BLS monthly supplemental tables — **Table 1C**, at
`https://www.bls.gov/cpi/tables/supplemental-files/c-cpi-u-YYYYMM.xlsx`, with prior years in
`archive-YYYY.zip` on the same page. Each file prints the index **as it stood at that
release**, for the reference month and the one before it.

* xlsx: 2021-11 → present (parsed from the `Indent Level` header and the two dated index
  columns)
* pdf: 2017-07 → 2021-10 (parsed with `pdfplumber`; only the current-month column is taken,
  because the header layout does not extract reliably and the previous-month column is
  ambiguous when a month is skipped)
* nothing before 2017-07 — `archive-2012` … `archive-2016` contain no C-CPI-U table at all

107 files → 4,680 rows in `p8_vintage(item_code, ym, pub_ym, value, source)`, publications
2017-07 … 2026-07. `pub_ym` labels the release by *its* reference month, so **`ym == pub_ym`
is the Initial estimate**. One caveat on the pdf era: `pdfplumber` drops inter-word spaces in
some vintages ("Allitems"), so item names are matched on a space-stripped normalisation as
well as the plain one; the only unmatched row across all 107 files is a year legend.

**Searched and not found:** BLS publishes no consolidated "C-CPI-U revision history" table
(neither on `bls.gov/cpi/additional-resources/chained-cpi…` nor as a standalone xlsx). The
vintage reconstruction above is the substitute.

### Hierarchy — why it is hardcoded

`cu_item` cannot supply the parent map for these 29 codes. In `cu.item` every major group sits
at `display_level` 0 alongside `SA0`, so nothing hangs off All items at all, and P0's
nearest-previous-level rule assigns `SAC`/`SAD`/`SAN`/`SAS`/`SA0E` a spurious `SAG` parent.
`su.item`'s own display levels are also wrong for this purpose — they flatten New vehicles
into a sibling of Private transportation. P8 pins the parent map explicitly (`PARENT` in the
source), mirroring the indent levels printed in Table 1C, which are stable and authoritative
for exactly these series.

### Coverage

All 29 su items exist in `cu_series` at the US-city-average level, so coverage is the full
intersection: **29 items**, 23 expenditure-category + 6 commodity-and-service-group
aggregates. All 8 major groups are present.

`is_partition` marks the **finest subset that still tiles 100%** of the index. Starting at
`SA0`, a node is replaced by its su children only when those children account for ≥99% of its
relative importance. That yields **15 items summing to 100.0%**: Food at home, Food away from
home, Alcoholic beverages, Shelter, Fuels and utilities, Household furnishings and operations,
Apparel, Private transportation, Public transportation, Medical care commodities, Medical care
services, Recreation, Education, Communication, Other goods and services. Private
transportation stays whole because su publishes only one of its children (New vehicles, 3.8%
of 14.8%) — descending would silently drop motor fuel, used cars and insurance.

Weights are December relative importances from `cpi_weight` (latest `weight_year`, currently
2025), used for display and for the decomposition only — never to build an index.

### Formulas

Both indexes are taken as published; nothing is re-aggregated.

```
cpi_u_yoy(i,t)      = (P_it   / P_i,t-12   - 1) * 100        P    = cpi_item_month.idx_nsa
ccpi_u_yoy(i,t)     = (C_it   / C_i,t-12   - 1) * 100        C    = p8_obs_latest.value
gap_yoy(i,t)        = cpi_u_yoy - ccpi_u_yoy                          (percentage points)

cpi_u_idx_rel(i,t)  = P_it / P_i,1999-12 * 100
ccpi_u_idx_rel(i,t) = C_it / C_i,1999-12 * 100               (= C_it, the series' own base)
gap_cum(i,t)        = (cpi_u_idx_rel / ccpi_u_idx_rel - 1) * 100      (percent)

long-run gap        = (cpi_u_idx_rel/100)^(1/yrs)  -  (ccpi_u_idx_rel/100)^(1/yrs), in pp/yr
```

`gap_cum` is a ratio, not a running sum of `gap_yoy`; it is the cumulative percent by which
the fixed-weight index has outrun the superlative one since the chained base month.

The CPI-U leg is NSA, matching the C-CPI-U, which BLS never seasonally adjusts. All 12-month
lags are **calendar-aligned joins on `YYYY-MM`**, never row offsets — 2025-10 has no CPI, so
row arithmetic would silently shift a month (the calendar-complete index rule).

`M13` annual-average rows are dropped, matching `cpi_obs`.

### Decomposition

At the latest final month the all-items gap is split into the relative-importance-weighted sum
of the 15 partition items' gaps plus a residual:

```
2025-09:  total +0.001 pp  =  weighted components -0.030 pp  +  residual +0.031 pp
```

The residual is what upper-level substitution *between* the 15 partition categories, plus
weight-reference timing, contributes beyond the within-category gaps. It is an accounting
identity, not a causal split.

### Known limitations

1. **The gap is not pure substitution.** It also contains the CPI-U's weight-reference lag
   (which changed character in 2023 when BLS moved from two-year to single-year weights), the
   Laspeyres-vs-Törnqvist formula difference itself, and the fact that the chained index is
   estimated rather than final for recent months. Reporting it as "how much consumers
   substituted" would be wrong.
2. **Only 29 categories, and they overlap.** No leaf-level chained index exists. Rows in the
   heatmap nest, and the commodity/service rows double-cover the total.
3. **Category-level gaps are noisier than the aggregate** and flip sign routinely. Only the
   all-items series has a long-run interpretation with external support.
4. **Recent months move.** The initial-to-final revision to the 12-month change averages
   0.274 pp — bigger than the average gap. Treat anything after the last final month as
   provisional, and prefer the final-stage month for rankings (the JSON does).
5. **Level revisions are cumulative.** `rev_pct` in `p8_revision` compares the level published
   for that month then and now; because the whole index path is revised together, it is not a
   clean per-month statistic. `rev_yoy_pp` is the one to quote.
6. **October 2025.** There is no CPI for 2025-10, and no C-CPI-U either — with one exception:
   `SETA01` (New vehicles) has an October value in both surveys (a handful of CPI series are
   priced from secondary sources and survived the collection gap), so `p8_gap` has exactly one
   2025-10 row. Everything else is absent by design, and YoY for 2026-10 will be null.
7. **Vintage history starts 2017-07.** Earlier initial prints are not recoverable from BLS.
   Our own `p8_obs` vintages start with pull 22 on 2026-08-19 and will accumulate from here.

### Re-running

```
cd $CPI_ROOT && ./p8_chained.py                # normal monthly run
                ./p8_chained.py --history     # + rebuild vintages from the full archive (~45 MB, cached)
                ./p8_chained.py --force       # re-download su.* and rebuild even if unchanged
                ./p8_chained.py --no-vintages # flat files only, skip the supplemental step
```

Idempotent: a second run on unchanged data stores 0 new `p8_obs` rows and rewrites the derived
tables identically. Exit 0 if all validations pass, 2 otherwise.

### Dashboard notes

The heatmap is the headline panel: diverging colour scale centred on zero, and it must be
centred on zero — the sign is the whole story. Sort rows by `sort_sequence` (already done in
the JSON) and consider showing only `section == 'expenditure'` by default, with the six
commodity/service rows behind a toggle, since they re-cover the same total.

Label the last months with their stage. Anything not `final` should be visually provisional,
and the ranking panels already use the latest final month (`ranking.as_of`) rather than the
newest month.
